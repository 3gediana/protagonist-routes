# 夜间批量跑 / 早上验收 — 调度脚本用法（睡前工作流落地）

对应交接文档第八节"睡前批量跑 / 早上一口气验收"。4 个文件：

| 文件 | 作用 |
|---|---|
| `night_manifest.txt` | 实验清单。每行 `名字 \| flags`，只写区别于对照的变量。 |
| `night_run.ps1` | GPU 编排器：读 manifest，串行跑每一臂，补齐公共 flags，写 metrics/log/ckpt + `night_status_<tag>.txt`。 |
| `night_launch.ps1` | 睡前一键：预检 + 把 night_run 注册成 schtasks 后台任务（断 ssh 不死）。默认只预检，加 `-Go` 才真启动。 |
| `scripts/night_analyze.py` | 早上验收：遍历这一轮 metrics，出同口径对比表 + YES/PARTIAL/NO 判定。 |

## 节奏
1. 睡前：改 `night_manifest.txt`（把今晚要验的猜想排成臂）。
2. 预检：`powershell -ExecutionPolicy Bypass -File night_launch.ps1`（看队列、显存、预计时长，不启动）。
3. 启动：确认无误 → `... night_launch.ps1 -Go`。
4. 早上：`python3 scripts\night_analyze.py --metrics-dir metrics --arms <逗号分隔臂名>`（或 `--manifest night_manifest.txt`）。

## 关键约束 / 踩过的坑
- 长任务必须 schtasks 后台；`Start-Process`/`Start-Job`/`&` 在 ssh 会话里随断连被杀。
- metrics 追加写：night_run 每臂跑前自动删同名旧 metrics/log，保证干净。
- **没有 `--device cpu`**：device 由 `PPOConfig.use_cuda`（恒 true）定，无 CLI 覆盖 → CPU 不能跑训练，只能跑分析。所以 CPU 旁路只用于 night_analyze / 历史分析 / oracle 录制，不能并行 CPU 训练（除非先加 flag 重编译）。
- 8GB 显存：默认串行。单组 n_envs=8 占用需实测后再决定能否并行（night_run 每臂打印 nvidia-smi 余量，跑一晚即可读出）。
- 命名统一 → 早上一个 analyze 脚本自动对比。停止：`Stop-ScheduledTask -TaskName dp_night; taskkill /IM deep_protagonist_train.exe /F`。
- night_launch 用 `Register-ScheduledTask`（而非 schtasks.exe）注册任务——同样是 Task Scheduler 后台任务、断 ssh 不死，但规避了 schtasks `/tr` 里路径带空格时的嵌套引号坑。
