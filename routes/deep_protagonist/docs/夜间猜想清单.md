## C1 · trigger-cost 抗乱按 ★最直击诊断
- **猜想**：按一下离散动作几乎零成本（`trigger_cost` 默认 **0.001/步**），所以网络乱按（实测 water_plot 空按上万次）。提高触发成本 → 只在有用时才按 → 熵↓、专化↑。
- **臂**：`--trigger-cost 0.002` / `0.005` / `0.01`（对照 0.001）。可与 mask 叠加：`--survive-first-mask --survive-first-thresh 0.35 --trigger-cost 0.005`。
- **反 Goodhart**：这是成本不是奖励，不可刷分；过高会把所有动作压死 → 看 score 是否崩、NOOP 是否飙。

## C2 · 关掉 dead-action-floor 让头专化
- **猜想**：floor（默认 **0.005**，coef 1.0）持续把"没人用的动作"概率往上托，可能正是熵居高不下的元凶。关掉看头是否自然专化。
- **臂**：`--ppo-dead-action-floor 0` / `0.001`（对照 0.005）。
- **风险**：floor 本是防"后期动作被永久饿死"的。关掉要盯后期 unlocks 是否反而塌（防灾难性遗忘红线）。

## C3 · 熵系数调度
- **猜想**：`ent-coef` 默认 **0.01**（给 fresh init 调的），持续高熵阻止收敛。降它让头专化。
- **臂**：`--ent-coef 0.005` / `0.002` / `0.0`（对照 0.01）。
- **风险**：太低会过早坍缩回觅食吸引子。和 C1/C2 是三条不同路径治同一个"熵太高"病，建议同晚一起验、看谁性价比高。

## C4 · critic warmup（价值先行）
- **猜想**：信用分配失败部分是 value head 没校准。先纯 critic 更新 N 步再开策略训练。
- **臂**：`--critic-warmup 200` / `500`（对照 0）。对 fresh 也有意义，不止 BC→PPO。

## C5 · repertoire-shaping 广度脉冲扫
- **猜想**：广度 PBRS 默认 **0.5**（D-136 设）。加强能否撬动恒零深链（crop/follower/cook）。
- **臂**：`--ppo-repertoire-shaping 0` / `1.0` / `2.0`（对照 0.5）。
- **反 Goodhart**：势函数，只付每种机制首次，上界 10，刷不了。

## C6 · 针对性 shaping（点火恒零通道）
- 已写好的 PBRS（默认全 0），各自针对一条卡死的链：
  - `--ppo-night-shaping 0.5`（夜间庇护，shelter 0%）
  - `--ppo-warmth-shaping 0.5`（保暖，破代码注释说的 ~6000 步冻墙，逼向便携保暖=衣服）
  - `--ppo-hunt-shaping 0.5`（陆地狩猎链）
  - `--ppo-day-shaping 0.5`（白天觅食）
- **臂**：各开一组对全 0。先验"哪条链最值得点火"，再决定保留哪个进基线。

## C7 · tier-gate 课程（工具门控建造）
- **猜想**：`--tier-gate` 让高级建造必须先有工具 → 形成自然课程，逼出"采矿→造镐→建造"工具链。
- **臂**：`--tier-gate`（对照 off）。

## C8 · 环境压力结构
- **thirst-decay**（默认 **12/min**）：D-040 发现高 decay 时 drink 自然主导。臂 `--thirst-decay 8` / `16`。
- **nutrition**（默认 off）：`--nutrition` 开双营养条+狩猎，改变生存压力维度（蛋白/维生素衰减、debuff、死亡宽限）。
- **weather**（默认 off）：`--weather` 开下雨耦合链（影响保暖/水）。
- 注意：这些**改世界 = 改了对照基准**，要单独成组，别和纯算法臂混在一张对比表里比 score。

## C9 · BC 暖启动线 ★CPU 旁路的真正用途
直击诊断：把"离散头从随机起步"换成"从会吃会建的克隆策略起步"。三段式：
1. **录 demo（CPU，可整夜和 GPU 并行）**：`--policy scripted`（或 settler）`--record-demos demos\oracle_<seed>.bin`。纯 rollout 不训练 → 吃 CPU 不抢显存（首次跑要确认它不 init CUDA）。→ 这就是 `night_cpu.ps1` 干的事。
2. **BC 克隆（GPU，一次性 prep）**：`--policy bc --bc-demos demos\*.bin --bc-out checkpoints\bc.pt --bc-epochs 8 --bc-trigger-weight 5`。
3. **PPO 暖启（GPU，进夜跑队列）**：`--load checkpoints\bc.pt --critic-warmup 300 --ent-coef 0.003` ＋ KL 锚定 `--ppo-kl-ref checkpoints\bc.pt --ppo-kl-coef 0.1`（防 PPO 跑回觅食吸引子——代码注释实测过 ent 2.9→7.9、bldg 崩）。
- **臂**：`bc_kl0`(无 KL) / `bc_kl01`(0.1) / `bc_kl03`(0.3)，都带 `--load bc.pt --critic-warmup 300 --ent-coef 0.003`。
- ⚠ night_run.ps1 写死 `--policy ppo`，所以"第2段 BC 克隆"不走夜跑队列（它是 `--policy bc`），单独 prep；夜跑队列里的 bc 臂都是 `--policy ppo --load bc.pt`。

# D · 结构/代码级猜想（要写代码 + 重编译，不是纯旗标）
> 深挖源码后的机制级根因 + 改造方向。都受铁律约束：**网络不重置、旧奖励不删、加参数走 warm-start surgery（新列零初始化，旧行为字节级不变）**。
> 这些不能进今晚的纯旗标队列，是"先写代码的下一阶段"清单。

## 机制级根因发现（先摆事实）
1. **共享 trunk 梯度打架 ★最可能的根因**：`obs → Linear encoder → GRUCell → {cont_mean, disc_logits, value, successor}`。连续头(走路)和离散头(动作)**完全共享 encoder+GRU**（只有 value/successor 是独立 branch）。单个 Adam、单个 lr、合并熵。
   → 走路有密集梯度（alive/explore/势函数每步都给），离散动作梯度稀疏且噪声大 → 共享表征被"走路"目标主导，离散头在一个为走路调好的表征上学不出专化。**这正好解释"连续头学会逛、离散头还在掷骰子"。**
2. **eat/drink 是邻近门控的**：eat=收割附近熟植物、drink=附近河水。离体征低但不在食物旁时，强制 eat 是空触发——真正缺的是"体征低→导航到看得见的水/食物"。obs 里明明有 nearest_water(145-147)/plants(39-66)，但没有把"渴时朝水走"接成密集梯度。
3. **obs 一半是 SpatialMemory 认知图**（384/582 维）：占比极大，但没验证它真在帮忙。
4. **Successor-Features ψ 头已存在**（D-123，detached trunk 训练，`--sf-coef`）：option/迁移的机器已经搭了一半。

## D1 · 离散头解耦（直击根因1）★最该先写
- **改造**：给离散头一条**独立小 trunk**（从 GRU 输出再接一两层只服务 disc_logits），或对共享 trunk 做**梯度手术**（disc loss 对 trunk 的梯度单独缩放/PCGrad 去冲突），或**离散头单独 lr / 单独 Adam param_group**。
- **预期**：离散头能在不被走路目标拖着走的表征上专化 → 熵↓、eat↑，且不动连续头既有行为。
- **warm-start**：新 trunk 层零初始化或恒等初始化，旧 cont/value 路径不变。

## D2 · 体征条件导航势函数（直击根因2）
- **改造**：加 PBRS `Φ = -dist_to_nearest_water`（仅当 thirst<阈值时计入）+ 食物同理。镜像 PE 里已验证的 `approach_tree_reward`/`approach_worksite_reward`（只付净接近、来回振荡=0、不可刷分）。
- **预期**：把"渴了→朝看得见的水走"接成密集梯度，补上 mask 只锁动作、却不引导移动的缺口。和 survive-first mask 是互补的（mask 管离散、势函数管连续）。
- **反 Goodhart**：势函数 + 体征门控，最优策略不变、不可空刷。

## D3 · 内在动机（探索稀有状态，点亮科技树）
- **改造**：RND（random network distillation）或对 SpatialMemory 格子做 count-based bonus → 奖励"没见过的状态"。
- **动机**：cook/mine 需要进洞、找矿——当前 `DP_EXPLORE_REW=0.03` 是最粗糙版。内在奖励能把 agent 推进 caves/ore 区，让 5 个科技树动作有机会被触发到。
- **反 Goodhart**：内在奖励随访问次数衰减（count-based 天然衰减 / RND 预测误差天然下降），不能在原地刷。

## D4 · options / 分层（用上已有的 ψ 头）
- **改造**：高层策略选子目标(find_water / find_food / gather / build)，低层执行；或用 ψ·w 的后继特征做子目标发现。ψ 头(D-123)已在、且 detached 训练不动冠军，是现成的脚手架。
- **风险**：最大改造量；建议在 D1/D2 验证"是不是架构问题"之后再上。

## D5 · 动作条件辅助损失（forward model）
- **改造**：加一个"给定 (h, 离散动作) 预测下一帧关键 obs（vital 变化/库存变化）"的小辅助头。
- **预期**：逼离散头的表征变得"有意义"（能预测后果），间接治专化；辅助头 detached trunk 或小权重，不动主策略。

## D6 · 自动课程（替代 tech-tree 全开/全关）
- **改造**：按里程碑达成度**渐进解锁**科技树（cook→mine→axe…），而非 D-136 的一次性全开。当前 23 类全开可能稀释了离散头（呼应 manifest 里的 locktech 隔离臂——那是旗标版的粗测；自动课程是代码版）。
- **依赖**：先看 locktech 旁路臂的结果，若"锁小动作集"确实救早期，再投资写自动课程。

## D7 · log_std / 连续头噪声调度
- **现状**：`log_std` 是 state-independent 可学习向量(3)。BC 暖启时注释说它会膨胀(2.9→7.9)毁克隆。
- **改造**：给 log_std 加下界 clamp 或单独的小 lr，防连续头噪声把离散头的信用淹没。小改动、低风险，可配合 D1。
