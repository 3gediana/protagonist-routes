1. 先学会怎么看

先分 4 类

  • 训练主指标： 例如 avg_fitness。
  • 行为事件指标： 例如 drank_water_events。
  • 研究解释指标： 例如 signal_action_mi。
  • 性能指标： 例如 total_ms。

最稳的阅读顺序

  • 先看任务主指标有没有动。
  • 再看配套指标是否一起支持这个解释。
  • 最后才看总 fitness。
别只看 fitness： fitness 是混合总分。它变好了，不一定代表你关心的那个行为真的变强了。

3. 系统机制地图：除了记忆，还加了什么

先建立一个总画面： 这个项目不是“只有一个神经网络在乱走”，而是神经脑 + 身体状态 + 资源世界 + 社会互动 + 生态压力 + 进化 一起作用的系统。记忆只是其中一块，而且它必须和其它机制配合才有意义。

世界与时间

地形不是纯装饰，会影响移动成本和可达性；世界也在往连续时间方向走，所以行为不是只有“按一次按钮”那么简单，而是跟 dt 和持续时间有关。

生存机制

主角不只是“活着就行”，而是要处理血量、口渴、受伤、取暖、恢复。这让“找水、回火边、回巢”变成真实需求，而不是脚本规定的任务。

资源与工具链

世界里有资源、树、石头、可搬运物体、工具制作、投掷、狩猎。这样主角不是只会移动，而是可能形成“采集 → 搬运 → 制作 → 使用”的链条。

基地与聚落机制

base、stockpile、nursery、campfire、worksite、progression 这些机制一起定义了“家”“营火”“工地”“发展阶段”这些概念，所以系统才能朝原始聚落而不是随机生态箱发展。

通信与合作

有 signal 层，也有会合、共同在场、共同狩猎、工地贡献这些机制。它们的目标不是做“装饰性信号”，而是让合作有可观测后果。

生态压力

背景物种、捕食者、猎物、病原体、昼夜、季节都会改变环境压力。这样训练出来的行为更像“在真实环境里应付问题”，而不是只对单一奖励函数取巧。

主角脑、背景物种脑、进化三者是什么关系

你可以把系统里的“智能部分”分成两层看：

  • 主角脑： 当前路线里主角有自己的脑结构、记忆通路、DNC 和专门感知。
  • 背景物种脑： 背景 species 走的是另一套更通用的 NEAT 路线。
  • 进化器： 它不直接“替主角思考”，而是根据表现保留好的个体、淘汰差的个体，再通过交叉和变异产生下一代。

所以这不是“一个固定模型上线推理”，而更像“许多个体在世界里竞争，表现好的脑结构被保留下来”。

基地、营火、工地、progression 为什么重要

如果没有这些机制，主角最多学会“找吃的、躲危险”。但你真正想看到的是更高一级的行为，比如：

  • 把材料搬回共同位置
  • 围着火生存和恢复
  • 在工地持续投入材料
  • 随着世界阶段推进，解锁新任务和新资源

这就是为什么系统里要有 base / nursery / campfire / worksite / progression 这些看起来“不是 AI 本体”的机制：它们定义了 AI 可以理解和争夺的社会空间。

信号、合作、贡献记录为什么不是可有可无

如果只有奖励，没有“谁做了贡献”的记录，系统很容易出现搭便车问题：真正干活的人和路过的人拿分差不多。

所以项目里会逐步加入：

  • 谁发了信号
  • 谁到场响应了信号
  • 谁对狩猎造成了真实伤害
  • 谁给工地送了材料

这些东西不是“锦上添花”，而是为了让合作能被正确奖励。

疾病、昼夜、季节这些机制到底在干嘛

它们的作用不是把世界弄复杂而已，而是防止系统学出太机械的固定套路。

  • 疾病： 让个体和病原体出现军备竞赛压力。
  • 昼夜： 让同样的行动在不同时间成本不同。
  • 季节： 让资源和环境条件不总是恒定。

简单说：这些机制的作用是让主角必须“理解世界在变”，而不是只记一条固定路线。

4. 这个项目是怎么训练的

最关键一句： 这条 protagonist 路线当前主训练方式更接近进化训练，不是常见课堂上那种“拿标签做反向传播的监督学习”。
一代训练大致发生什么
  • 第 1 步： 读取配置，决定世界大小、机制开关、奖励权重、是否 resume checkpoint。
  • 第 2 步： 创建或恢复 protagonist population，同时创建背景物种 population。
  • 第 3 步： 每一代跑多个 episode；每个 episode 会把主角和背景物种一起放进世界。
  • 第 4 步： 世界按 substep_dt 连续推进，期间累计 reward、行为指标、trace、DNC 摘要等。
  • 第 5 步： 把多个 episode 的表现汇总成每个个体的 fitness。
  • 第 6 步： 用 selection + crossover + mutation 产生下一代，并定期保存 checkpoint。

你可以把它理解成：不是在调一个模型的梯度，而是在筛选一整群不同的脑，留下更适应这个世界的那些。

训练时到底在优化什么

当前训练参数里，reward 不是只看一项，而是多项组合：

  • 生存
  • 进食
  • 探索 / 内在动机
  • 战斗
  • 合作
  • 通信
  • 工地靠近 / 工地完成
  • 共同狩猎

这也是为什么后面你不能只看 avg_fitness：因为它本来就是这些目标混合后的总分。

常见训练入口配置怎么理解
配置用途适合理解成什么
protagonist_ecology_train_smoke.toml极短训练接线验收，不是最终能力证明
protagonist_ecology_train_survival_foundation.toml生存基础课先学活下来
protagonist_ecology_train_camp_building.toml营地建造课学会搬运、围火、工地闭环
protagonist_ecology_train_camp_building_evolve.toml更正式的建造训练在更完整训练循环里真正进化

为什么训练要多 episode，而不是一代只跑一次

因为世界有随机性。只跑一次，某个个体可能只是“运气好”。

多 episode 的意义是：让系统更看重稳定表现，而不是一次碰巧拿高分。

5. 这个项目怎么测试

测试不只是一种： 这个项目里至少有代码级测试、短 smoke、专门 eval 世界、ablation、traceprobe 这几层。
第一层：代码级测试

这层回答的是“代码有没有接错”。当前 route 里已经有不少专门测试，例如：

  • test_protagonist_ecology_config.cpp：配置解析是否正确
  • test_goal_manager.cpp：目标管理逻辑是否正常
  • test_checkpoint_resume.cpp：checkpoint 是否能真恢复
  • test_memory_ablation_eval.cpp：ablation 任务派生是否正确
  • test_memory_trial_layer.cpp：DNC micro-task 层是否正常
  • test_protagonist_brain_v3_shell.cpp：BrainV3 最小壳层是否没接崩

这层很重要，但它只能证明“系统没坏”，不能证明“系统真的学会了”。

第二层：smoke run

smoke run 的意思不是“训练完成”，而是“我先用一个很小的配置跑一下，看整条链有没有打通”。

例如 protagonist_ecology_train_smoke.toml 就适合验证：

  • 世界能不能正常启动
  • 训练循环能不能跑完
  • CSV 和 trace 能不能产出
  • 行为计数是不是非空
第三层：eval 世界

eval 世界是专门拿来问一句：它学到的是规则，还是只是记住了训练地图？

当前已经有几类 eval 配置：

  • protagonist_ecology_eval_generalization.toml
  • protagonist_ecology_eval_sparse_terrain.toml
  • protagonist_ecology_eval_timing_shift.toml

它们会改几何布局、地形、资源节奏或时间条件，用来测试泛化，而不是只看训练世界里会不会走固定路线。

第四层：ablation

ablation 的意思是“把系统里某一块先关掉，再看表现会不会掉”。

这比“某个指标升了”更有解释力，因为它直接在问：这块机制到底有没有贡献。

当前最典型的就是 memory ablation：关掉 spatial / episodic / social / goal 之一，看 fixed-task 的主指标是否下降。

第五层：traceprobe

当某个结果不对时，traceprobe 不是继续盲猜，而是回到事件级和 agent 级轨迹里查：

  • 信号有没有真的发出
  • 材料有没有真的送到
  • goal 有没有在该切换时切换
  • 记忆写入有没有真的发生

它更像“黑盒训练里的调试显微镜”。

6. 真实运行与“生产环境”怎么理解

当前代码里已经区分了 train / eval / live
角色它在语义上是什么当前怎么用
train训练世界用来进化 population，产生新一代
eval评估世界换环境检验泛化，不应把它和正式训练混在一起
live长期运行世界更像开放运行 / 展示 / 观察环境
run() 现在真实怎么分支

当前 runtime 的分支逻辑很直接：

  • 如果开了 memory ablation，就走 专项 ablation 入口
  • 否则如果 evolution.generations > 0，就走 训练入口
  • 否则就只是初始化世界，然后按 preview_duration_seconds 把世界往前推进

这意味着：现在的 live 角色已经存在，但它当前更像“长期运行世界”，不是一套完整的线上继续学习系统。

“生产环境里继续学”这个想法能不能做

原则上能做，但要分清两种含义：

  • 含义 A： live 世界只是继续运行，个体在世界里靠记忆、状态、生态互动继续适应。这个现在就能做一部分。
  • 含义 B： live 世界里的模型权重 / 基因也在线继续更新。这个现在还不是完整闭环。

如果直接让线上个体边跑边改脑，风险很大：

  • 可能突然学坏
  • 可能把生态平衡直接打崩
  • 出问题时很难回滚和定位
  • 你也会分不清“这是新能力”还是“偶然漂移”
更安全的“生产环境继续学习”方案应该是什么

对这个项目来说，最合理的不是“live 里无约束自我修改”，而是受控的持续学习：

  • 第 1 步： live 世界继续跑，持续收集轨迹、行为、环境数据。
  • 第 2 步： 在旁路训练区或 shadow world 里，用这些数据继续训练 / 继续进化候选 population。
  • 第 3 步： 用 eval 世界、ablation、关键任务指标去审查候选版本。
  • 第 4 步： 只有通过门槛的新 checkpoint，才替换到 live。
  • 第 5 步： 保留旧 checkpoint，随时能回滚。

你可以把它理解成：不是让“线上个体自己乱改脑”，而是让 live 提供真实经验，再由受控训练系统慢慢学习。

如果以后真的要这样跑，最推荐的顺序

最稳的流程： train → eval → live → shadow continual learning → gated promotion

这很像真正工程里的做法：先离线学，再上线观察，再受控更新，而不是一上来就在线自我进化。

7. 训练主指标

fitness.csv · 最基础总分
字段含义怎么判断

DNC 摘要字段
字段它是什么怎么判断
dnc_usage_mean_avg平均槽位使用率看“记忆板整体用了多少”

9. 记忆 / DNC / Ablation

memory_ablation_results.csv 怎么看

这张表是当前最关键的记忆验证表。它会按 task 和 variant 输出各项平均结果。

字段含义用途
task任务名当前有哪些固定任务
variantbaseline / no_spatial / no_episodic / no_social / no_goal关掉哪类记忆后的对照组
primary_metric该任务最重要的主指标值第一优先级
primary_metric_name主指标字段名告诉你这任务先看什么
avg_fitness / best_fitness总分辅助，不是第一优先级
survived_avg平均存活数看危险规避类任务
avg_health_ratio / avg_hydration_ratio平均健康 / 水分比例看生存状态是否同步改善
drank_water_events_avg平均喝水事件回水任务核心字段
deposits_avg / worksite_completion_events_avg平均交付 / 工地完成事件回工地与建造任务关键字段
signal_emit_events_avg / signal_response_events_avg / signal_co_attendance_avg平均信号事件、响应、会合看信号是否真的有作用
dnc_usage_mean_avg / dnc_read_peak_avgDNC 活动摘要只做辅助解释
各任务的主指标怎么配
  • WaterReturn： 先看 drank_water_events
  • DangerAvoidance： 先看 survived
  • WorksiteReturn： 先看 worksite_completion_events
  • SignalResponse： 先看 signal_response_events

所以比较 baseline 和 ablation 时，先看对应任务自己的主指标，再看 fitness。

为什么短 smoke 里“关掉记忆反而更高分”不能说记忆有害

短训里记忆输入维度很多，而 NEAT 还没学会利用它时，这些输入更像噪声，所以早期可能出现“关掉记忆反而更容易采样”的情况。

这说明短 smoke 更适合做接线验收，不适合直接下“记忆有害/有益”的科研结论。

11. 研究型统计

这部分容易误读： 很多字段是“解释系统结构”的，不是“证明某个行为已经学会”的硬证据。
advanced_stats.csv
  • shannon_diversity：物种分布多样性。
  • fitness_variance：强弱差距有多大。
  • avg_age：平均年龄。
  • avg_exploration：平均访问格子数，近似看探索范围。
  • behavior_complexity：简化动作序列复杂度，越高表示不那么重复。
  • species_count：物种数。
  • alive_ratio：存活比例。
emergence_audit.csv
  • signal_behavior_mi_avg：信号与动作的平均互信息。
  • modulatory_usage_ratio：有调制能力的活体比例。
  • modulatory_corr：当前实现是 proxy，不是直接神经调制激活。
  • pred_prey_fitness_corr：捕食者和猎物 fitness 相关性，粗看红皇后。
  • heavy_tasks_completed：重任务完成数。
  • host_immunity_pathogen_virulence_corr：宿主免疫与感染暴露 proxy 的相关性。
  • species_dig_preference_var：当前还是 proxy，不能当直接“挖掘偏好方差”。
  • cave_occupancy_ratio：洞穴占用比例。
  • hunt_success_rate：捕猎成功率。
comprehensive/*.csv 核心文件
  • oee_complexity.csv：节点数、连接数、隐藏节点、结构多样性。
  • population_stats.csv：空间熵、行为熵、fitness 熵、能量方差、感染比例等。
  • info_theory.csv：signal_action_mi、terrain_behavior_mi、infection_behavior_mi。
  • coevo_stats.csv：捕食-猎物 fitness、red_queen_corr、hunt_success_rate。
  • disease_arms_race.csv：毒力、菌株数、免疫率、免疫记忆大小、感染率。
  • species_profile.csv：每个物种的平均位置、能量、感染比例、洞穴比例、脑结构、偏好参数。
物种快照与系谱

species.jsonl 会记录每代的 species_count，以及每个物种的 members、living、avg_fitness、best_fitness。

phylo_tree.jsonl 会记录 species_born、species_alive、species_extinct 事件，用来重建谱系。

12. 关键参数：为什么同一个指标不能乱比

参数会影响什么为什么重要
episodes_per_generation统计稳定性episode 数不同，均值可比性就会变差
episode_duration_seconds行为次数上限时长不同，drank_water_events、deposits_total 等不能直接横比
substep_dt连续时间步长会影响积分、事件密度和共同在场时间累积
signal_co_attendance_radius会合判定半径半径越大，越容易被算进响应/会合
signal_co_attendance_window_seconds响应判定时间窗时间窗越长，signal_response_events 越容易成立
worksite_completion_reward建造动机强度奖励越大，系统越可能优先学建造闭环
social_proximity_radius合作邻近判定会影响 cooperative_co_presence_seconds 的增长速度
joint_hunt_radius围猎判定范围会改变联合捕猎被奖励的难易度
memory ... enabled某类记忆是否参与ablation 比较时最关键
compute.agent_decision_threads运行速度主要影响性能，不直接改变行为定义

13. 实战判读模板

会不会回水

主看： drank_water_events

辅助： avg_hydration_ratio 上升，dehydrated_avg 下降，survived_protagonists 上升。

会不会建工地

先看： deposits_total

再确认： worksite_completion_events、completed_worksites。

信号有没有用

主看： signal_response_events

辅助： signal_co_attendance、signal_action_mi、ablation 分离。

狩猎是否学会

主看： hunt_successes 或 hunt_success_rate

不要只看： hunt_attempts。

记忆是否真的有用

黄金标准： baseline 与 ablation 的任务主指标明显分离。

DNC 数值： 只能做辅助证据。

训练是否整体变好

同时满足： avg_fitness 稳定上升、关键行为持续非零、存活不崩、不是单代偶然峰值。

建议阅读顺序：先看“系统机制”“怎么训练”“怎么运行”，再看“主角行为指标”和“记忆 / Ablation”。
