Neural Eco · 指标与判读说明

这页专门回答 3 个问题：这个字段是什么、它怎么统计出来、它能不能用来判断某个行为真的发生了。内容基于当前代码里真实存在的输出字段整理。

怎么看 文件地图 训练指标 主角行为 记忆与 Ablation 生态模块 研究型统计 关键参数 判读模板
先记一句： 想判断“行为有没有发生”，优先看真实事件计数；想判断“系统是不是更复杂了”，再看互信息、熵、多样性这些研究统计。

1. 先学会怎么看

先分 4 类

  • 训练主指标： 例如 avg_fitness。
  • 行为事件指标： 例如 drank_water_events。
  • 研究解释指标： 例如 signal_action_mi。
  • 性能指标： 例如 total_ms。

最稳的阅读顺序

  • 先看任务主指标有没有动。
  • 再看配套指标是否一起支持这个解释。
  • 最后才看总 fitness。
别只看 fitness： fitness 是混合总分。它变好了，不一定代表你关心的那个行为真的变强了。

3. 训练主指标

fitness.csv · 最基础总分
字段含义怎么判断
generation第几代横轴
min_fitness本代最低分看底部是不是还在大面积翻车
avg_fitness本代平均分最适合看整体训练是否前进
best_fitness本代最高分看天花板，但容易被单个幸运个体拉高
evolution.csv · 主角与背景物种一起看

表头是 generation,min_fitness,avg_fitness,best_fitness，后面还会拼接每个背景物种的 _avg 和 _best。

如果主角越来越强，但背景物种全崩，说明可能不是“生态更聪明”，而是环境被打穿了。

perf.csv · 这是性能表，不是行为表
字段含义用途
total_ms一整代总耗时看总运行成本
eval_ms评估阶段耗时看行为仿真有多贵
repro_ms繁殖阶段耗时看进化更新有多贵

4. 主角行为指标

这是当前 route 最关键的一张表： protagonist_behaviors.csv。
注意： 这张表里有的是“事件次数”，有的是“最终状态”，有的是“DNC 摘要平均值”。不要把它们当成同一种数直接横比。
生存与资源闭环
字段它是什么怎么判断
episodes本代评估 episode 数比较 run 前先确认一致
total_protagonists合并所有 episode 的主角总数分母
survived_protagonists最后活下来的主角数先看能不能活到最后
drank_water_events真实喝水事件数判断“会不会回水源”的硬指标
deposits_total总交付次数看有没有把资源搬到目标位置
deposits_stick木棍交付次数看材料链细分
deposits_stone石头交付次数看材料链细分
completed_worksitesepisode 结束时最终完成的工地数偏结果
worksite_completion_events运行过程中新增完成工地事件数更适合证明建造闭环真的发生过
active_fires当前活跃营火数量看聚落设施结果，不等于点火事件次数
采集、制造、攻击、狩猎
字段它是什么怎么判断
chop_attempts尝试砍树说明开始尝试
chop_successes成功砍树成功比尝试更重要
craft_attempts尝试制作看是否进入工具链
craft_successes成功制作说明制造闭环通了
throw_attempts尝试投掷只说明动手了
throw_hits投掷命中比 attempt 更像真正战术行为
hunt_attempts尝试狩猎看是否进入追击链
hunt_successes成功狩猎判断会不会真正完成捕猎
信号与合作
字段它是什么怎么判断
signal_emits当前实现更接近“被记录到的 emitter 数”不完全等于所有发信号事件总数
signal_response_events主角以 RespondSignal 为目标并在时窗内到达信号附近的响应事件判断“真的响应了信号”的关键字段
signal_co_attendance在时窗内进入信号会合区域的累计次数看是否围绕信号聚集
cooperative_co_presence_seconds多人共同在场的累计秒数说明同地协同停留，但不等于任务有效完成

最稳的说法： 想证明信号有用，优先看 signal_response_events，再用 signal_co_attendance 和研究统计里的互信息补强。

DNC 摘要字段
字段它是什么怎么判断
dnc_usage_mean_avg平均槽位使用率看“记忆板整体用了多少”
dnc_write_peak_avg写入权重峰值看写时会不会强聚焦某槽位
dnc_read_peak_avg读取权重峰值看读时会不会强聚焦某槽位
dnc_precedence_peak_avg时间链接前序峰值看顺序记忆链条热点
dnc_samples摘要采样次数样本量
最重要提醒： DNC 数值高，不等于记忆真的帮了任务。它只能说明“记忆系统在活动”，真正的证据要看 ablation 后任务主指标是否下降。

5. 记忆 / DNC / Ablation

memory_ablation_results.csv 怎么看

这张表是当前最关键的记忆验证表。它会按 task 和 variant 输出各项平均结果。

字段含义用途
task任务名当前有哪些固定任务
variantbaseline / no_spatial / no_episodic / no_social / no_goal关掉哪类记忆后的对照组
primary_metric该任务最重要的主指标值第一优先级
primary_metric_name主指标字段名告诉你这任务先看什么
avg_fitness / best_fitness总分辅助，不是第一优先级
survived_avg平均存活数看危险规避类任务
avg_health_ratio / avg_hydration_ratio平均健康 / 水分比例看生存状态是否同步改善
drank_water_events_avg平均喝水事件回水任务核心字段
deposits_avg / worksite_completion_events_avg平均交付 / 工地完成事件回工地与建造任务关键字段
signal_emit_events_avg / signal_response_events_avg / signal_co_attendance_avg平均信号事件、响应、会合看信号是否真的有作用
dnc_usage_mean_avg / dnc_read_peak_avgDNC 活动摘要只做辅助解释
各任务的主指标怎么配
  • WaterReturn： 先看 drank_water_events
  • DangerAvoidance： 先看 survived
  • WorksiteReturn： 先看 worksite_completion_events
  • SignalResponse： 先看 signal_response_events

所以比较 baseline 和 ablation 时，先看对应任务自己的主指标，再看 fitness。

为什么短 smoke 里“关掉记忆反而更高分”不能说记忆有害

短训里记忆输入维度很多，而 NEAT 还没学会利用它时，这些输入更像噪声，所以早期可能出现“关掉记忆反而更容易采样”的情况。

这说明短 smoke 更适合做接线验收，不适合直接下“记忆有害/有益”的科研结论。

7. 研究型统计

这部分容易误读： 很多字段是“解释系统结构”的，不是“证明某个行为已经学会”的硬证据。
advanced_stats.csv
  • shannon_diversity：物种分布多样性。
  • fitness_variance：强弱差距有多大。
  • avg_age：平均年龄。
  • avg_exploration：平均访问格子数，近似看探索范围。
  • behavior_complexity：简化动作序列复杂度，越高表示不那么重复。
  • species_count：物种数。
  • alive_ratio：存活比例。
emergence_audit.csv
  • signal_behavior_mi_avg：信号与动作的平均互信息。
  • modulatory_usage_ratio：有调制能力的活体比例。
  • modulatory_corr：当前实现是 proxy，不是直接神经调制激活。
  • pred_prey_fitness_corr：捕食者和猎物 fitness 相关性，粗看红皇后。
  • heavy_tasks_completed：重任务完成数。
  • host_immunity_pathogen_virulence_corr：宿主免疫与感染暴露 proxy 的相关性。
  • species_dig_preference_var：当前还是 proxy，不能当直接“挖掘偏好方差”。
  • cave_occupancy_ratio：洞穴占用比例。
  • hunt_success_rate：捕猎成功率。
comprehensive/*.csv 核心文件
  • oee_complexity.csv：节点数、连接数、隐藏节点、结构多样性。
  • population_stats.csv：空间熵、行为熵、fitness 熵、能量方差、感染比例等。
  • info_theory.csv：signal_action_mi、terrain_behavior_mi、infection_behavior_mi。
  • coevo_stats.csv：捕食-猎物 fitness、red_queen_corr、hunt_success_rate。
  • disease_arms_race.csv：毒力、菌株数、免疫率、免疫记忆大小、感染率。
  • species_profile.csv：每个物种的平均位置、能量、感染比例、洞穴比例、脑结构、偏好参数。
物种快照与系谱

species.jsonl 会记录每代的 species_count，以及每个物种的 members、living、avg_fitness、best_fitness。

phylo_tree.jsonl 会记录 species_born、species_alive、species_extinct 事件，用来重建谱系。

8. 关键参数：为什么同一个指标不能乱比

参数会影响什么为什么重要
episodes_per_generation统计稳定性episode 数不同，均值可比性就会变差
episode_duration_seconds行为次数上限时长不同，drank_water_events、deposits_total 等不能直接横比
substep_dt连续时间步长会影响积分、事件密度和共同在场时间累积
signal_co_attendance_radius会合判定半径半径越大，越容易被算进响应/会合
signal_co_attendance_window_seconds响应判定时间窗时间窗越长，signal_response_events 越容易成立
worksite_completion_reward建造动机强度奖励越大，系统越可能优先学建造闭环
social_proximity_radius合作邻近判定会影响 cooperative_co_presence_seconds 的增长速度
joint_hunt_radius围猎判定范围会改变联合捕猎被奖励的难易度
memory ... enabled某类记忆是否参与ablation 比较时最关键
compute.agent_decision_threads运行速度主要影响性能，不直接改变行为定义

9. 实战判读模板

会不会回水

主看： drank_water_events

辅助： avg_hydration_ratio 上升，dehydrated_avg 下降，survived_protagonists 上升。

会不会建工地

先看： deposits_total

再确认： worksite_completion_events、completed_worksites。

信号有没有用

主看： signal_response_events

辅助： signal_co_attendance、signal_action_mi、ablation 分离。

狩猎是否学会

主看： hunt_successes 或 hunt_success_rate

不要只看： hunt_attempts。

记忆是否真的有用

黄金标准： baseline 与 ablation 的任务主指标明显分离。

DNC 数值： 只能做辅助证据。

训练是否整体变好

同时满足： avg_fitness 稳定上升、关键行为持续非零、存活不崩、不是单代偶然峰值。

建议阅读顺序：先看“主角行为指标”和“记忆 / Ablation”，再看研究型统计。
