# ADR-0001 · 地形是真实物理，不是渲染装饰

- **状态**：已采纳
- **日期**：2026-05-18
- **背景**：在讨论 2.5D 地形时出现过两种思路 —— "地形只是渲染漂亮"，和"地形是世界规则的一部分"。

---

## 决策

**地形（高度图 + 山洞）是世界状态的一等公民，参与物理与感知，不只是渲染。**

具体含义：
1. `World` 持有 `TerrainLayer`，提供查询接口 `height(x, y)` / `slope(x, y)` / `inCave(x, y)`
2. **物理影响**：
   - 移动速度按当前坡度衰减
   - 上坡能量消耗增加
   - 视线被高地形遮挡（视野计算时按高度差判断）
   - 山洞内：从外部不可见、获得隐藏属性、视野受限
3. **感知影响**：`TerrainPerception` 把"自身高度 / 坡度向量 / 是否在洞内 / 视线方向上的高度变化"作为输入喂给网络
4. **渲染**：viz 层用等距投影呈现 2.5D，但**不真做 3D**——避免引入 OpenGL 复杂度

---

## 为什么这样决定

### 选项 A：地形只是渲染装饰

✅ 实现简单
✅ 个体逻辑保持 2D
❌ 个体行为完全不受地形影响 → 山只是花瓶，"群居在山洞"这种现象不可能涌现
❌ 用户明确说"我希望看到不同高度的群体差异"——纯渲染做不到

### 选项 B（采纳）：地形是真实物理

✅ 个体可以基于地形进化策略：洞穴隐藏者、高地侦察者、平原游牧者
✅ 视觉差异和行为差异联动 —— "群居山洞"不是渲染骗局，是真的因为山洞有庇护属性
✅ 地形可以作为奖励工程的杠杆（把高价值资源放在山顶逼出爬山策略）
❌ 实现复杂度增加 —— 视野遮挡、能量公式、感知输入维度都要扩展
❌ 调参面增加 —— 地形修正系数需要花时间调

### 选项 C：完整 3D 物理

❌ 课设范围严重超标
❌ 与 OOP 课设主题偏离

---

## 影响

- `IWorld` 接口必须包含地形查询方法（M0 抽象时就要预留）
- `IPerception` 必须支持地形相关的输入（M0 接口预留 TerrainPerception 类位置）
- M5 阶段集中实现地形物理与渲染
- 山洞作为特殊地形结构，可能需要单独的 cave_mask 或更复杂的"上下层"结构 —— 详见 M5 文档
