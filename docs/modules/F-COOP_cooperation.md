# F-COOP · 合作机制

> 让"围猎"、"协同搬运"、"分工"成为可能。

- **难度**：🔴 高
- **确定性档**：🔴 低（围猎涌现是 NeurIPS 难题）
- **前置条件**：F-COMM 完美完成
- **状态**：📋 待开发

---

## 一句话

设计需要多个个体协同才能成功的任务（重型猎物、需要多人合力的资源），通过"成功后参与者共享奖励"的机制让合作行为有进化优势。

---

## 你会看到什么效果

### 完美版（🔴 SSR）
某种资源（"重型食物"）单 agent 推不动，但 3 个一起推可以。一段进化后，agent 会"等待"——看到重型食物后徘徊不走，等待同伴。同伴到达后协同推动。
更进一步：分工出现 —— 某些 agent 专门"召唤"（用信号），某些"执行推动"。

### 标准版（🟡 大概率）
"群聚"现象：重型食物附近会聚集多个 agent，但不一定是真协同——可能只是因为奖励信号让它们都被吸引。
答辩话术："观察到群聚现象，但是否真协同需要更精细的相关性分析。"

### 降级版（🔴 兜底）
合作没涌现，但**重型食物机制本身让世界更丰富**。降级方案：把"合作"改为"显式机制"——任何接近重型食物的多个 agent 自动获得部分奖励，进化"接近重型食物"的行为，作为合作的"原型"。

---

## 实现要点

### 重型食物 / 多人任务

```
src/core/world/layers/resource/
└── HeavyResourceItem.cpp        要 N 个 agent 同时贴近才能"采集"
```

机制：
- 重型食物有 `required_workers` 字段（如 3）
- 当 N 个 agent 在 radius 内同时存在 ≥ K tick → 资源被采集
- 奖励均分到所有参与者
- 单 agent 接近无效（不会被吃掉）

### 共享奖励组件

```
src/core/reward/
└── SharedTaskReward.cpp
```

订阅 `HeavyResourceCollected` 事件，根据参与者列表分配奖励。

### 与 F-COMM 配合

如果 F-COMM 已启用，agent 可以发"召唤信号"。配合 SharedTaskReward，发召唤信号成功导致协同 → 发信号者也获得奖励 → 召唤行为被强化。

### 分工统计

观测：
- 某些个体经常发召唤信号 → 标记为"召唤者"基因
- 某些个体经常响应召唤 → 标记为"执行者"基因
- 用基因变异 + 角色分化作为答辩素材

## 🧠 你的补充点

| 项 | 决定什么 |
|---|---|
| **required_workers** | 默认 3。太小退化为单 agent，太大永远凑不齐 |
| **完成时间窗口 K** | 协同维持多少 tick 算成功 |
| **奖励均分 vs 按贡献** | 均分简单，按贡献（存在时间长）更细腻 |

---

## ⚠️ 易踩坑

1. **协同窗口太短**：3 个 agent 同时贴近 1 tick 就奖励 → 退化为"碰撞奖励"，不是真协同
2. **奖励太丰厚**：协同奖励太高 → agent 围着重型食物挤一团，正常觅食被忽略
3. **吃白食问题**：4 个 agent 完成 3 人任务，第 4 个白吃 → 设置只奖励主要贡献者（贴近时间最长的 N 个）
