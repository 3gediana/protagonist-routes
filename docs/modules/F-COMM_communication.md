# F-COMM · 通信信号场

> 让个体能"喊话"。试图涌现原始语言。

- **难度**：🔴 高
- **确定性档**：🟡 中（信号能发能收）+ 🔴 低（信号涌现"语义"）
- **前置条件**：M5 完美完成
- **状态**：📋 待开发

---

## 一句话

地图上多一层信号场（衰减场，K 个通道）。个体可以在自己的位置写入信号向量，附近的个体能感知信号场叠加值。**信号的"含义"完全靠进化决定**。

---

## 你会看到什么效果

### 完美版（🔴 跑出来吹爆）
某个特定信号 A 经常和"我看到食物"绑定。同伴感知到 A 后会朝信号源移动 → **信号 A ≈ "这里有吃的"**。
另一个信号 B 经常在遇到捕食者时发出，附近同伴会逃散 → **信号 B ≈ "危险"**。
答辩话术："我没有定义任何符号的含义。是进化让特定信号在特定情境下被使用，并被接收方做出对应反应。"

### 标准版（🟡 大概率）
个体会发信号，信号场动态丰富，**但语义不一定收敛**。可能出现"个体喜欢发信号但接收方反应混乱"——信号的发出和接收没有形成稳定的因果。
答辩话术："观察到广泛的信号活动，但语义聚类还不显著——这正是通信涌现需要更长进化时间的实证。"

### 降级版（🔴 兜底）
即使语义没涌现，**信号场动态可视化本身就是好看的视觉效果**。地图上一层流动的色彩涟漪，配合统计面板（哪种信号被哪种 agent 发得最多），仍然有得讲。
答辩话术："这一层呈现了通信的'潜在底物'。语义涌现是后续工作。"

## 实现要点

### 信号场层

```
src/core/world/layers/signal/
├── SignalLayer.h / .cpp           IWorldLayer 实现
├── SignalField.h / .cpp           K 个通道的衰减场
└── SignalDecay.h / .cpp           衰减规则
```

数据结构：
```cpp
class SignalField {
    Grid<Vec<K>> field;        // 离散化网格存储 K 维信号向量
    float decay_rate;          // 每 tick 信号强度衰减
    float diffusion_rate;      // 信号向邻近格扩散

    void emit(Vec2 pos, Vec<K> signal);
    Vec<K> sample(Vec2 pos, float radius) const;   // 邻域聚合
    void tick();                                    // 衰减 + 扩散
};
```

K 推荐 = 4-8。太少表达力不够，太多调参困难。

### 个体能力扩展

```
src/core/capability/
├── EmitSignalCapability.h / .cpp     读取 brain 输出后 K 维 → 写入信号场
└── (无需新感知 - 用 SignalPerception)

src/core/perception/
└── SignalPerception.h / .cpp          读取自身位置周围信号场叠加 → 网络输入
```

输出维度从 M5 的 (vx, vy) 增加 K 维 → (vx, vy, signal_1, ..., signal_K)
输入维度增加 K 维 → 接收到的邻近信号叠加

**NEAT 必须能动态扩展输入输出维度**——M3 设计时已确保。

### 奖励设计（关键中的关键）

通信涌现成功 vs 失败，**90% 取决于这里**。

❌ **错误设计**：发信号有奖励
→ 进化出"无脑发信号"机器，信号没有意义

✅ **正确设计**：
- 发信号有**轻微能量代价**（防止无脑发）
- **接收方**根据信号做出"正确反应"时被奖励
- "正确反应"由情境决定（不是你写的固定规则！）

具体方法：
```toml
[F-COMM]
emit_energy_cost = 0.1
# 接收方奖励：如果接收信号后 N tick 内做了"对自己有利的事"
# （吃到食物 / 躲过捕食者 / 找到资源），把这次行为的奖励一部分回溯给信号源
backpropagation_factor = 0.3
```

这是 **kin selection** 的算法版——只有信号"有用"时，发信号者才间接受益。

### 视觉表现

在 viz 层加 SignalLayerRenderer：
- 信号场用半透明色彩涟漪叠加在地图上
- 每个通道一种基色（K=4 时用 RGB+黄）
- 强度对应不透明度
- 可在 ControlPanel 切换显示哪个通道

### 信号-情境相关性分析（用于答辩）

写一个脚本分析：
- 给定时刻 t，agent 在情境 C 下发出信号 S 的概率
- 信号 S 出现后，附近 agent 在情境 C 中能量变化均值
- 用互信息（mutual information）量化"信号-情境"相关性

**如果互信息 > 阈值 → 涌现成功**
**如果互信息 ≈ 0 → 信号是随机噪音**

## 🧠 你的补充点

| 项 | 决定什么 |
|---|---|
| **K（信号通道数）** | 表达空间大小。小（2-3）容易涌现但单调，大（8+）丰富但难收敛 |
| **decay_rate** | 信号持续多久。慢衰减容易污染场，快衰减信号传不远 |
| **diffusion_rate** | 信号传多远。决定通信半径 |
| **接收方奖励回溯系数** | 0% = 完全孤狼进化，100% = 完全集体主义。中间值（20-50%）最有意思 |
| **emit_energy_cost** | 防止滥发的关键。太低 → 噪音；太高 → 没人发 |

## ⚠️ 易踩坑

1. **信号通道数过多**：K=20 时几乎不可能涌现，**K=4 是甜点**
2. **接收方奖励回溯实现**：需要短期内追踪"信号源 agent_id"。用环形缓冲存最近 N tick 的信号 emit 历史
3. **信号场内存**：200×200 网格 × K=4 通道 × float = 600KB，OK；但 1000×1000 时是 16MB，注意
4. **过早评估**：50 代就看不出语义涌现，**至少跑 300 代**才有判断价值
5. **奖励信号回环**：信号源因为接收方反应得到奖励，强化了发信号；接收方因为反应正确得到奖励，强化了反应——这个回环必须**信号是真有用**才闭合，**否则两边都白学**。所以底层情境必须真的能让信号有信息含量

## 答辩话术

**讲得好**：
> "我没有定义任何符号或语言。我只是给了它们'发声'的能力，让接收方在做出对应反应时获得奖励——奖励的一部分回溯到信号发出者。这个简单的机制让特定信号和特定情境之间慢慢绑定起来。屏幕上这层流动的色彩，就是它们之间的'对话'。"

**降级讲得好**：
> "通信涌现是 NeurIPS 论文级别的难题，OpenAI 用了几千 GPU 几个月。在我们这个尺度下，能看到广泛的信号活动但语义聚类还不稳定，这本身就是这个问题难度的实证。如果有更多算力和时间，下一步就是优化奖励回溯机制。"

无论结果如何，**都有得讲**。
