# 开发路径（ROADMAP）

> 这是整个项目最重要的文档。它解决三件事：**做什么、什么时候做、为什么这样排序**。

---

## 一、核心约束（来自你的明确要求）

| 约束 | 含义 |
|---|---|
| **地图必须连续** | 浮点坐标，不是网格。**从 M1 开始就是连续的，不存在"先做离散网格再升级"** |
| **真实 2.5D 地形** | 地形不是渲染装饰，**是世界规则的一部分**：高度影响移动、视野被遮挡、有山洞这种特殊结构 |
| **网络拓扑可进化** | 个体大脑用 NEAT，神经元和连接的数量自己长出来 |
| **复杂交互** | 除了趋食，必须支持**合作、交流、对抗** |
| **未来不确定** | 你现在不知道最终会加多少功能，架构必须**足够松散**，能像拼乐高一样加新东西 |

## 二、开发哲学：基线 + 模块仓库

放弃"P0→P9 一条线"的死板规划。改成两段式：

### 🟦 基线（必做，按顺序完成）

这是无论你最终想加什么功能，都必须先有的底座。

> 注：各阶段表格和说明里出现的具体数值（种群规模、tick 数、reward 权重、倍率目标等）默认都只是**起始示例**，不是预先验证过的真值；后续应以真实实验结果和调参记录为准。
>
> 额外说明：按 [ADR-0005](adr/0005-defer-visualization-until-mechanics-stabilize.md)，当前执行顺序调整为**先机制、后可视化整合**。也就是先完成 `M1 -> M3 -> M4 -> M5` 的 headless-first 核心机制，再集中补 `M2` 风格的展示层整合。

| 阶段 | 标题 | 核心产出 |
|---|---|---|
| **M0** | 脚手架与抽象 | 事件总线 / 接口 / 配置 / 日志 / 插件框架 |
| **M1** | 连续 2D MVP | 浮点世界 + 固定拓扑 NN + 简单 GA，跑通进化循环 |
| **M2** | 可视化接入 | raylib 渲染 + 适应度曲线实时显示 |
| **M3** | NEAT 升级 | 替换 Brain 实现，拓扑进化 + 物种分化 |
| **M4** | 多线程加速 | headless 训练池 + 异步个体决策 |
| **M5** | 真实 2.5D 地形 | 高度图 + 山洞 + 移动/视野受地形影响 + 等距渲染 |

完成机制基线并补完可视化整合后，你就有一个完整的、可演示的、能跑出基础进化行为的系统。

### 🟨 模块仓库（按兴趣选，可任意组合）

底座做完后，所有"我想加 XXX"的功能都变成独立模块，互不依赖。每个模块一张卡片，文件在 [modules/](modules/) 下。

#### 🤝 交互类（让世界从单调进化升级到社会演化）
- `F-COMM` 信号 / 信息素地图 — 个体可在地图留下衰减信号 → 进化出原始"语言"
- `F-COOP` 合作机制 — 共同任务奖励 → 进化出团队分工
- `F-FIGHT` 对抗机制 — 攻击/防御/能量转移
- `F-PRED` 捕食者-猎物 — 多物种共进化
- `F-TOOL` 工具与可移动物体 — 拾取石头堆叠 → 涌现"建筑"
- `F-LEARN` 终身学习 — 拉马克 vs 达尔文开关，生命周期内可微调权重

#### 🌍 环境类（让世界更有"故事性"）
- `F-DAY` 昼夜循环
- `F-SEASON` 季节
- `F-DISEASE` 疾病传播 — 邻接传染 debuff，逼出社交距离基因
- `F-RESOURCE` 资源衰竭再生 — 逼出可持续 vs 短视策略分化
- `F-CAVE` 洞穴系统 — 山洞作为庇护所/陷阱

#### 🔬 观测类（让进化"看得见"，是项目差异化的核心）
- `F-TREE` 物种树 — 谱系图，看灭绝/分支/优势祖先
- `F-HEAT` 行为热力图 — 群体经过频率叠加
- `F-FORK` 平行宇宙 — 任意时刻分叉存档
- `F-STAT` 高级统计 — 多样性、香农熵、Lyapunov 指数

#### 🎬 演示类（答辩闪光点）
- `F-GOD` 上帝按钮 — 实时干预面板
- `F-LLM` LLM 解说员 — 接 OpenAI 兼容 API 实时生成解说
- `F-REPLAY` 录制 / 回放系统
- `F-COMPARE` 对照实验 — 左右分屏跑两个世界
- `F-CURRICULUM` 课程学习 — 逐级解锁难度

#### ⚙️ 算法类（如果基础进化卡住，这些是救命稻草）
- `F-NOVELTY` 新颖性搜索 — 奖励"和别人不一样"，破死亡螺旋
- `F-COEVO` 协同进化 — 多种群对抗式进化
- `F-NSGA` 多目标进化 — 同时优化多个适应度

## 三、为什么基线必须按这个顺序

### 反向思考：什么会让你被迫推倒重来？

| 风险 | 应对策略 | 体现在 |
|---|---|---|
| 可视化和逻辑搅在一起 | core/viz 两层从根上分离 | M0 |
| 一上来就 NEAT 跑不通排查难 | M1 先用固定拓扑，验证进化循环 | M1 → M3 |
| 没事件总线 | M0 第一件事就是事件总线 | M0 |
| 离散网格写死 | 浮点坐标从 M1 就用 | M1 |
| 训练演示混在一起 | headless / interactive 双运行时分离 | M0 |
| 地形写死成"装饰" | 地形作为世界一等公民，不是后加 | M5 设计、M0 接口预留 |
| 加新交互要改核心 | 所有交互通过事件 + 能力插件，核心不知 | M0 |

### 当前执行顺序（2026-05-19 更新）

用户已明确要求：**不要做半成品可视化**。因此当前默认推进顺序改为：

```text
M1 收尾验收        ✅
→ M3 NEAT 升级     ✅
→ M4 多线程 / 异步决策  ✅
→ M5 地形核心机制     ✅
→ 可视化整合（沿用 M2 原则）  ← 下一步
→ modules（12 个已 MVP）
```

这样做不是否定 M2，而是把 M2 从“早期调试层”改成“后期统一展示层”。

### 替换演习法

**M3（NEAT 替换固定拓扑）** 和 **M5（地形升级 World）** 是故意安排的"接口压力测试"。

- 如果 M0 接口设计经得起这两次替换 → 后续所有 F-* 模块都很顺
- 如果 M0 设计糟糕 → M3/M5 会暴露问题 → **早暴露 < 晚暴露**

### 每阶段必须能独立运行

每个 M 结束都有可执行产物。**拒绝"写到 M5 才第一次跑起来"这种灾难。**

## 五、你的补充点（每阶段都给你留了空间）

不是所有事 AI 助手都帮你做。每个阶段都有"你必须自己思考"的部分。这正是课设需要的"自己做的工作"。

## 六、未来扩展的接口承诺

这些是 M0 必须把"位置"占好的事，避免后续被迫重构核心：

- ✅ 事件总线 `IEventBus`，所有交互可订阅
- ✅ 能力系统 `IAgentCapability`，每种行为（信号、攻击、繁殖）是可挂载的能力
- ✅ 感知系统 `IPerception`，每种感官（视觉、听觉、地形、信号）独立可组合
- ✅ 奖励系统 `IRewardComponent`，每种奖励是独立组件，可叠加
- ✅ 世界扩展点 `IWorldLayer`，地形 / 食物 / 信息素 / 物体 都是世界的"层"，可独立加
- ✅ 观察者 `IObserver`，所有数据导出 / 录制 / 统计都通过订阅事件实现，不污染核心

> 详见 [ARCHITECTURE.md](ARCHITECTURE.md) 的"插件化与扩展点"章节。

## 七、重构哲学

### 何时重构？

- 一个接口被三个以上模块依赖且其中一个出问题 → 重构接口
- 单文件超过 500 行 → 拆分
- 配置项膨胀到 50+ 个 → 拆分配置文件

### 何时不重构？

- 接口被两个模块依赖且都能跑 → 不重构
- 你觉得"丑"但功能没问题 → 不重构（课设有 deadline）

### 何时该写 ADR？

任何不可逆决策（选 raylib 而不是 SFML / 用 NEAT 而不是 CMA-ES / 逻辑层是否感知地形）都写 ADR 到 [docs/adr/](adr/)。一年后看代码不会问"当时怎么想的"。
