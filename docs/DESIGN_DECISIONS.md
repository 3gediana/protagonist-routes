## 顶层设计原则（这些不可妥协）

### 1. 三层分离

```
core      ←  纯逻辑，永远不依赖渲染
viz       ←  只读 core，订阅事件
runtime   ←  组装层，决定 headless 还是 interactive
```

理由：训练时 0 渲染开销；演示时插入可视化。

### 2. 一切通过事件

所有跨模块通信优先走 `IEventBus`，不优先走直接函数调用。
新增观测、统计、录制都是订阅事件，**不污染核心**。

### 3. 多层世界

`World` 不是一个大对象，是多个 `IWorldLayer` 叠加。
新增世界元素 = 加一层（地形/食物/信号场/物体），不改其它层。

### 4. 三件套组件化

- `IPerception` 感知组件（视觉/听觉/地形）
- `IAgentCapability` 能力组件（移动/吃/攻击/发信号）
- `IRewardComponent` 奖励组件（生存/吃饭/合作/新颖）

新增行为 = 加新组件，**不改 Agent 类**。

### 5. 配置驱动

所有可调参数走 TOML，不写死代码。
模块开关也是配置项，**不重新编译就能开关功能**。

### 6. 接口压力测试

M3 替换 Brain（固定拓扑 → NEAT）和 M5 升级 World（加地形物理）是故意安排的接口压力测试。
**早暴露设计问题 < 晚暴露**。

## 重要权衡记录

### 选 raylib 而不是 SFML / SDL2

- raylib API 更简洁，C 风格直接，AI 助手写得快
- 自带基础 UI、字体、3D primitive，免去造轮子
- SFML 更面向对象但 API 啰嗦，SDL2 太底层

### 选 NEAT 而不是 CMA-ES / 标准 GA

- NEAT 拓扑可进化是项目核心卖点（物种树可视化的来源）
- CMA-ES 是连续优化，不适合结构变化的问题
- 标准 GA 拓扑写死，缺少视觉震撼

### 选 TOML 而不是 JSON / YAML

- TOML 设计目标就是"人类编辑友好"，比 JSON 注释友好
- toml++ 是 C++ header-only 库，集成简单
- YAML 缩进敏感，C++ 生态没那么成熟

### 网络小但能做事——回应"小模型够吗"的疑虑

详见 ADR-0002。一句话：LLM 是百科全书，我们的网络是趋光性草履虫，问题尺度差几个数量级，**小网络足够**。

### 不做的事（明确放弃）

- HyperNEAT（复杂度过度）
- Spiking 神经网络（工程不稳定）
- 完整模块化大脑（调试地狱）
- 身体形态进化（偏离 OOP 主题）
- 真 3D 物理（用 2.5D 等距投影替代）
- 自研 GUI 框架（用 raylib 自带 + raygui）
